# v0.1.31

## Fix: member spawn on Harness 0.2.1-rc.2 (persona/toolFilter removed from start requests)

The first 0.2.1-rc.2 runtime matrix exposed a real break inside the line policy: captain tools loaded, but **no member ever executed** (`memberRequests: 0`, scenarios timed out). The recorded team state showed the cause:

```
spawnError: deers-agent-team: provider "spawn" cannot apply a member persona
  at spawnMember (lib/members.js)
```

`0.2.1-rc.2` removed `persona` and `toolFilter` from `SubagentStartRequest` **and** from `SubagentCapabilities` (`agentOptions`/`agentPreset`/`outputSchema`/`depthLimit` only). A continuable child's composition is now replayed only from a *historical descriptor*, so the start request can no longer dress a child. The plugin required `capabilities.persona`/`capabilities.toolFilter` and passed both fields on every spawn, so every member spawn failed with that error and the scheduler kept retrying silently.

Fix, capability-probed and generation-tolerant:

- The start request carries `persona`/`toolFilter` **only when the provider declares those capabilities** (hosts through 0.2.1-alpha.x). On rc.2+ they are omitted.
- The member setup hook (`installMemberSelectionRuntime`) now dresses the child on its own scoped context when the durable descriptor lacks either field: it installs the same `deployment:persona-prefix` section the host used to apply (`memberPersona(...)` from durable team state, so cold resume works too), and reapplies the member tool restriction (`memberToolFilter(maxDepth, restrictableToolNames(captain))`) with `childCtx.tools.restrict`. Older hosts persist both fields in the descriptor and replay them, so this branch stays dormant there and never double-applies.
- `installMemberSelectionRuntime` gained a `memberMaxDepth` argument so the self-applied deny list matches the configured delegation budget; the parent-chain guard continues to enforce depth in every host generation.

Verified: `pnpm typecheck`, 71 unit tests, `verify.mjs`, the metadata gates, and the 0.2.1-rc.2 runtime matrix (lifecycle, fallback, failure, captain-idle-wakeup, progressive-entry, web-approval, protocol-compatibility, stability) — see the result JSON archived under `docs/harness-0.2.1-rc.2/`.
