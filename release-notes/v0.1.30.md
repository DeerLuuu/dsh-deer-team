# v0.1.30

## Host line policy: one plugin build per 0.2.* line

The previous policy enumerated every individually verified host version in each of the 21 `@deepseek-ai/dsh-*` peer ranges. That made the profile-startup gate deny the plugin on every new host version — including same-line patch/pre-release bumps — so every DSH update required a plugin sync.

v0.1.30 switches to a **host line range**:

- `compatibility.json` gains `hostRange: "^0.2.0"`.
- Every dsh-* peer now declares that line range exactly once, plus exact arms only for targets **outside** the line (the legacy `0.1.x` hosts) — so any later `0.2.x` version, including a new `0.2.x-alpha/beta/RC` or patch, is admitted by the range without a plugin release.
- `scripts/compatibility.mjs` enforces the new contract structurally: the line range must appear exactly once, every off-line declared target must be enumerated, and every remaining arm must be an exact declared target — a floating arm such as `>=0.2.0` is rejected so a range can never absorb `0.3` by accident.
- `doctor.mjs` now reports a same-line host that was not individually verified as `host-line` (admissible, with a limit note) instead of `unsupported`; off-line hosts such as `0.3.0` still fail.

Only a line change (0.3, 0.4, …) still requires a plugin sync: add the new target, update `hostRange`, run the matrix. The tradeoff of the line policy is that an unknown same-line version is no longer stopped at startup — API breakage inside the line surfaces as the plugin's capability probes (`typeof` guards) or a loud `unsupported(...)` error instead of a startup denial.

Also in this release: `docs/maintenance-workflow.md` documents the line policy and the new `host-line` doctor verdict; `test/compatibility.test.mjs` covers same-line coverage, off-line enumeration, floating-arm rejection, and the doctor's line verdict.

Verified with `node scripts/compatibility.mjs`, `node scripts/readme-version.mjs`, `node scripts/release-metadata.mjs`, `node --test scripts/compatibility.test.mjs` (12 tests), `pnpm typecheck`, `pnpm test` (71 tests), and the runtime matrix on `0.2.1-rc.2`; packaged as `0.1.30`.
