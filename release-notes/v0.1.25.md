# v0.1.25

## Staged-plan approval fixes (v0.1.24 incident)

v0.1.24 added per-row contract validation at plan approval, but its integration had a self-comparison bug that blocked plan approval entirely, and it let plans express kinds that cannot be planned:

- **A row no longer overlaps itself.** The approve-time loop validated each staged row against the whole team *including that row*, so every write-kind row with `inScope` failed with `staged task "t3": inScope overlaps t3 at …`. Each row is now validated against the team without itself plus a `selfId` marker — the same pattern the running-team edit path already used.
- **Serialized same-scope rows pass in both directions.** The inScope overlap exemption only looked at direct dependencies, so a chain `impl1 → impl2 → impl3` sharing one scope was wrongly rejected when validating `impl1` or `impl3` (audit QG-12; the dead `pending-new` condition is gone). The exemption now follows the dependency closure in both directions: only genuinely concurrent same-scope writes conflict.
- **`repair` can no longer be planned.** A repair's `sourceTaskId`/`sourceFindingIds` only exist after a review fails, so a planned repair row could never satisfy its contract and dead-locked approval ("repair tasks require sourceTaskId and at least one sourceFindingId"). Plan and profile rows now reject `kind: repair` at creation with an actionable message (plan an implementation + review pair instead); repairs remain runtime-generated from failed reviews. The `create({plan})` schema enum no longer offers `repair`.
- **Staged rows are now editable with their full contract.** `deers_team_edit_plan update_task` accepts `kind`, `objective`, `acceptance`, `verify`, `inScope`, `outOfScope`, `round`, `deliverables`, `nonGoals`, `reviewedTaskId` and `coverageOf` while staged (empty string/array clears), and contract violations surface at edit time with the exact row id — so a rejected plan can be repaired in place instead of being discarded.
- Review rows that name a `reviewedTaskId` but do not list it in `dependencies` are rejected with the fix stated in the message.

Regression coverage: `test/staged-plan-contracts.test.ts` (10 cases) locks in no-self-overlap, both-direction serialization exemption, concurrent-conflict rejection, repair-in-plan rejection, review-dependency binding, and profile-plan contract acceptance. All 71 unit tests and the 47-check quality-gates TDD suite pass; the 0.2.1-alpha.2 runtime matrix stays green on the approve-exercising scenarios (`web-approval`, `stability`).
