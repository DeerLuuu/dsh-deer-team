# v0.6.0

## Blackboard filtering, grouping and automatic retention

The shared blackboard now supports the two things a long brainstorming round needs: finding the right entries and keeping the feed from growing forever.

### Filters and grouping

- **Kind chips**: all / note / idea / proposal / decision, each with its current count.
- **Author filter**: captain plus every author currently on the board.
- **Search**: case-insensitive match over entry content and author.
- **Grouping**: no grouping, group by kind, or group by member.
- **Model side**: `deers_team_blackboard_read` gains a `q` search parameter alongside the existing `author` / `kind` filters.
- The standalone `/deers-agent-team/` page gets author and kind filters plus a cleanup button.

### Automatic cleanup

New profile config:

```yaml
blackboardCleanup:
  enabled: true          # false = keep only the manual "Clean up" button
  intervalSeconds: 3600  # host scan interval
  retentionDays: 30      # entries older than this become eligible
  keepLatest: 10         # newest N entries always survive
  keepPinned: true       # pinned entries survive
  keepDecisions: true    # decision entries survive
```

- The host scans every active team on a timer and removes eligible entries under the team lock; `blackboard.lastCleanupAt` records the latest removal.
- Writes also run a lazy cleanup, and reads clean + persist when entries were removed, so boards stay bounded even without a timer service.
- The Web panel shows the active policy, the last cleanup time, and a **Clean up** button that triggers one manual pass (works even when automatic cleanup is disabled).
- Entry ids are never reused; clearing the board still does not reset the `bb-N` sequence.
- Defaults are on: 30-day retention, newest 10, pinned and decisions protected.
