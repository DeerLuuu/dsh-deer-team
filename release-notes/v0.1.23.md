# AgentTeams v0.1.23

Stable plugin release on npm `latest`. Adds the published Harness `0.2.1-alpha.1` cohort as a supported preview host; the recommended host stays `0.2.0-rc.2`.

- Declare `0.2.1-alpha.1` in `compatibility.json` as a `preview` target and enumerate it in every `@deepseek-ai/dsh-*` peer range.
- Fixes profile-startup denial: a host upgraded from `0.2.0-rc.2` to `0.2.1-alpha.1` refused to load this plugin, because the loader evaluates each `@deepseek-ai/dsh-*` peer against the runtime with `semver.satisfies(..., { includePrerelease: true })` and denies a bundle whose peers match nothing.
- Accept the preview cohort's aliased shared runtimes in the two non-DSH host peers: `@deepseek-ai/cordis@4.0.5-alpha.1` and `@deepseek-ai/schemastery@3.18.5-alpha.1` are prereleases of a later patch, so the previous `^4.0.2` / `^3.18.2` ranges rejected them and npm aborted installation with `ERESOLVE`.
- Open member transcripts through the owned navigation action: Harness 0.2.1 removed `ISessions.open`/`openSubagent`/`refreshSubagents` ("navigation belongs to view owners") and `uiWorkspace.openSession` is the surviving path. Declare `@deepseek-ai/dsh-client-ui-workspace` as an injected client service instead of relying on an unordered `ctx.get` lookup that silently degraded to a console warning.
- Retain the seven earlier supported hosts and the `0.2.0-rc.2` recommended host; an Alpha host can never be the ordinary-user recommendation.
- Publish the stable business API names (`TEAM_TOOL_NAMES`, `MEMBER_TOOL_NAMES`, `CAPTAIN_TOOL_NAMES`) from the package root and derive every tool-count assertion from them: the copied upstream fixtures still expected 14 team tools while this fork registers 18, so `pnpm verify:capabilities` and the `progressive-entry` runtime scenario failed on a stale number rather than on behavior.
- Keep the `0.2.0-rc.2` development baseline and pnpm overrides, as the release gate requires for a stable `latest` publish.

## Install

In Plugins → Add plugin, enter `deers-dsh-agent-team@0.1.23`. Use the npm official registry if a mirror has not synchronized the release. GitHub repository installation also includes the prebuilt entrypoints.

The host supplies its own core. Updating the global CLI does not update a desktop app's embedded core. A host that still runs `0.2.0-rc.2` needs no change; a host on `0.2.1-alpha.1` now loads this plugin without a version exemption and installs without `--legacy-peer-deps`.

## Verification scope

The host peer list is checked by `scripts/compatibility.mjs` and the release metadata by `scripts/release-metadata.mjs`; both run in `pnpm verify`. Runtime verification against the Alpha host uses the published-cohort matrix (`scripts/harness-runtime-verify.mjs --host-version 0.2.1-alpha.1`), recorded in [the 0.2.1-alpha.1 migration note](../docs/harness-0.2.1-alpha.1/README.md). Real provider credentials, browser interaction, and other operating systems remain outside this release's evidence.
