# v0.1.24

## Harness 0.2.1-alpha.2 support

A host upgraded to the published `0.2.1-alpha.2` cohort denied this plugin at profile startup: none of the 21 `@deepseek-ai/dsh-*` peer ranges listed the new runtime version. `0.2.1-alpha.2` is now declared in `compatibility.json` (track `preview`) and enumerated in every host peer range, so the loader admits the plugin again. The recommended host remains `0.2.0-rc.2`.

Beyond the version gate, `0.2.1-alpha.2` renamed the subagent lifecycle surface this plugin drives. `startContinuable` and `drainContinuableChildren` no longer exist anywhere in the host; the replacements are `startActivation(spec & { delivery })` and `drainChildren(parent, childIds)`. Member spawn now prefers `startActivation({ delivery: 'parent' })` (with the activation result promise neutralized, since member outcomes arrive through mailbox and agent events), member drain uses `drainChildren`, and both fall back to the previous-generation names so every earlier declared host keeps working. The member delegation guard now wraps every present start entry by name (`start`, `startContinuable`, `startActivation`, `prompt`) instead of a fixed pair, so a renamed delegation path on a future host cannot bypass the member depth budget.

Verified against the installed `0.2.1-alpha.2` runtime: `Symbol.for('dsh.subagent.deliverPrompt')`, `sendMessage(sender, targetId, content, options)`, `interrupt(targetSessionId, authority)`, `agent/created`, `agent/pre-step`, `agent/status`, `Agent.followup`, `tools.restrict().view().restrictableNames`, provider `prepareContinuable`/`capabilities.persona`/`capabilities.toolFilter`, and the client-side `uiWorkspace.openSession` / `layout.selectPanel` / `beginNavigation` / sidebar-right services all remain present.

## Safety and quality-gate fixes

- `deers_team_create` approval now defaults to `required`. Previously an omitted `approval` parameter silently skipped the user's Web plan review and started spawning immediately, contradicting the captain protocol; only an explicit `approval: "automatic"` runs without review.
- `deers_team_remove_member` no longer revives failed or cancelled tasks. It requeued every non-completed task of the removed member, wiping the verdict and findings of failed reviews and duplicating auto-created repairs; it now skips all terminal tasks, matching `deers_team_delete`.
- Reviews bind to the reviewed task. Creating a `kind=review` task now requires the reviewed task's id in `dependencies`, requires the reviewed task to be an `implementation` or `repair`, rejects assigning the review to the reviewed task's owner, and records `reviewedAttempt` when the reviewed task is already terminal. Completing a review verifies the reviewed task is still `completed` at the same attempt and that the reviewer differs from the owner.
- Evidence consistency: `round`, `findings[].line` and `commandsRun[].exitCode` are integer schemas, `round` must be a safe integer ≥ 1, and a `passed` command reporting a non-zero exit code (or a non-integer line/exitCode) is rejected before it can poison `team.json`.
- Workspace scans tolerate one damaged team directory: `findTeamByCaptain`/`findTeamByParticipant` skip (with a warning) unreadable team directories and the `archive` entry instead of failing every team tool in the workspace; the damaged team itself still fails loud when addressed directly.
- Staged plans can carry quality contracts: `create({plan})` task rows (and configured profiles) accept `kind`, `objective`, `acceptance`, `verify`, `inScope`, `outOfScope`, `deliverables`, `nonGoals`, `reviewedTaskId`, `sourceTaskId`, `sourceFindingIds` and `coverageOf` (plan-local ids are remapped to durable ids), and `deers_team_approve` validates every row through the same `validateCreateTask` contract. The recommended one-shot plan path can no longer produce gated-looking work with no gates.
- `inScope: ["."]` (whole workspace) is rejected for write kinds at creation.
- Escalation is resolvable: `deers_team_resume` (and `create_task({resume:true})`) now clears the `escalated` latch together with `halted`, so one `reject` verdict no longer makes a team permanently undeliverable.
- The standalone ops page renders its DAG with mermaid `securityLevel: 'strict'`, fully entity-escapes label text and restricts node ids to a safe charset with generated aliases, closing the stored-XSS chain through task ids/subjects.

## Manifest changes

- `compatibility.json`: `0.2.1-alpha.2` enters `supportedHosts` with track `preview`; ten declared targets in total.
- `package.json`: every `@deepseek-ai/dsh-*` peer enumerates the ten declared targets; development baseline and pnpm overrides stay at `0.2.0-rc.2`.
- Shared-runtime peers widened: the `0.2.1-alpha.2` host declares `~4.0.5-alpha.1` cordis and `~3.18.5-alpha.1` schemastery, and npm resolves those tilde ranges to the published `4.0.5-alpha.2` / `3.18.5-alpha.2` (dist-tags `dsh-0-2-1-alpha-3`), which semver never matches `^4.0.2`/`^3.18.2` and aborted installation with ERESOLVE. The peer ranges are now `^4.0.2 || 4.0.5-alpha.1 || 4.0.5-alpha.2` and `^3.18.2 || 3.18.5-alpha.1 || 3.18.5-alpha.2`, so both resolved generations install. The host's compatibility gate only inspects `@deepseek-ai/dsh*` peers, so this changes package-manager resolution, not profile admission.
- Client declarations and the compatibility seams in `src/harness-compat.ts`, `src/members.ts` and `src/tools.ts` are shared with the earlier declared hosts; no host-only branch was removed.
