# v0.6.2

## Docs: correct the DSH host version claims

The README and README_ZH incorrectly labelled the supported/current Harness as `0.3.2-rc.2` (and `0.3.2-alpha.*`), while the actual running host is **`0.2.2-rc.4`** on the `^0.2.0` line and `compatibility.json` still declared `0.2.0-rc.2` as recommended. This release makes docs and policy agree with the installed host.

- `compatibility.json`: `0.2.2-rc.4` is now the recommended target; `0.2.0-rc.2` moves to preview; `hostRange` stays `^0.2.0`.
- `package.json`: every `@deepseek-ai/dsh*` peer range now includes the exact `0.2.2-rc.4` arm.
- README / README_ZH version tables rewritten:
  - Recommended: Harness `0.2.2-rc.4` + AgentTeams `0.6.2`
  - Preview: `0.2.1-rc.2`, `0.2.1-alpha.2`, `0.2.1-alpha.1`
  - Previous recommended: `0.2.0-rc.2`
  - Legacy/older hosts unchanged.
- CLI install command is now `npm install --global @deepseek-ai/dsh@0.2.2-rc.4`.
- Desktop-app paragraph no longer claims a `0.3.2-rc.2` carrier; it points at the real target and the new evidence page.
- New evidence page: `docs/harness-0.2.2-rc.4/README.md` records the host identity, the public-subagent contract, activation evidence and the compatibility commands.

No plugin behavior changed. `node scripts/compatibility.mjs` now prints `0.2.2-rc.4` first, and `node --test scripts/compatibility.test.mjs` passes (12/12).
