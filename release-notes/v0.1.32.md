# v0.1.32

## Fix: member persona must be visible on the very first model request (0.2.1-rc.2)

The first 0.1.31 matrix run on `0.2.1-rc.2` spawned members and executed turns, but the fixture-classified member session showed one request with `isMember: false` before the persona appeared — and that single request made the fixture take the captain branch (`deers_team_create` is absent from a member's tools), which failed the member task; the captain then looped on `status` forever (2373 requests) because no report ever arrived.

Root cause: `0.2.1-rc.2` removed `persona` from `SubagentStartRequest`, and the plugin's fallback (installing the `deployment:persona-prefix` section from the member setup hook) runs **after** the child's first request is assembled — activating a continuable child starts driving it immediately. So the first member request had no persona.

Fix: when the provider has no `persona` capability, the member persona now rides in the **initial user message** (prepended to the welcome/assignment prompt), which is part of the start request and therefore present in the very first model request on every host. Older hosts still receive the persona as a system section via `request.persona` and are unchanged; the setup-hook section remains as a subsequent-request/compaction resilience layer.

The runtime fixture (`harness-runtime-llm.mjs`) now detects membership from either the system persona or the initial user prompt, because both are model-visible channels — this is a test-harness correction, not a product change.

Also: `scripts/harness-runtime-verify.mjs` gained an optional `--registry <url>` (default unchanged: the official npm registry) so the matrix can run where the official registry is unreachable; the chosen registry is recorded in the report. This run used a mirror because `registry.npmjs.org` timed out from this network.

Verified: typecheck, 71 unit tests, `verify.mjs`, metadata gates, and the full 0.2.1-rc.2 runtime matrix (lifecycle, lifecycle-cold-restore, fallback, fallback-cold-restore, failure, captain-idle-wakeup, progressive-entry, web-approval, protocol-compatibility, stability).
