# v0.2.1

## Fix: watchdog timer access without a hard `timer` injection

v0.2.0 failed to activate on the Harness profile with:

```text
cannot get property "timer" without inject
```

`watchdog-loop` read the timer helpers through `ctx.interval`, which Cordis only exposes to plugins that declare `timer` in their inject list. Adding a hard injection would make the whole plugin wait for the timer service in compositions that omit it, so the loop now resolves the service optionally through `ctx.get('timer')` and degrades to "manual scan only" when it is absent.

No protocol, state or tool-surface change beyond the fix: all v0.2.0 features (watchdog, Router-role captain, digest/recall, progress heartbeats, report batching) are unchanged.

Verified: `pnpm typecheck`, 94 unit tests, `pnpm build`, capabilities (18/18), and a successful profile activation on the installed 0.2.1 tarball.
