# v0.3.2

## Fix: plugin activation on the public subagent delivery contract

Harness builds that removed the private `dsh.subagent.queuePrompt` / `deliverPrompt` symbols and the targeted `drainChildren` method left the host plugin failing to activate:

```text
deers-agent-team: unsupported Harness subagent contract
(cannot install complete retired-member guard)
```

The client panel stayed mounted while every `deers_team_*` tool disappeared.

- `harness-compat.ts` now treats the public `sendMessage` seam as a complete delivery contract: it queues to an idle or cold-resumed member, steers a running one, and is guarded by the same retired-member check.
- When the host no longer exposes a targeted child drain, halt/stop falls back to `drainDescendants([captain])`, which closes admission and stops every descendant of the captain (the team roster) before reporting success.
- The continuable-member setup hook falls back to `agent/created` when the host has no `registerContinuableSetup`, and no longer rejects hosts that only expose `sendMessage`.
- A regression test simulates the send-only generation (setup via `agent/created`, queue delivery, retired guard, `drainDescendants`).

Verified on the running host: the host plugin reaches `active`, all tools are registered again, and the compatibility test suite passes (15/15).
